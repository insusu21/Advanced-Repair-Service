## 백엔드 (박시현) — `backend` 브랜치 `local/integration`

| 파일 | 바꾼 것 | 이유 |
|---|---|---|
| `ApiController` · `RepairService` | 접수 `?targets=`, 추가 사진 `?target=` 받기 | 사진이 전부 GENERAL로 저장돼서 에이전트가 PCB/모터 사진을 구분 못 했다 |
| `RepairService.target()` | `MECHANICAL`도 `MOTOR`로 저장 | 옛 이름으로 와도 받아 준다 |
| **새 API** `POST /api/repairs/{id}/approval` | 기사 진단 확인·반려 → 수리 중(REPAIRING), 본사 검토 요청 → MANUAL_REVIEW, 본사 회신 → REPAIRING | **진단 완료 → 수리 중으로 넘기는 API가 없어** 프론트 리포트 화면이 안 열렸다. 본문은 프론트가 원래 쓰던 `{target, action, comment}`. 기존 코드 스타일(권한 확인, 행 잠금, event/audit 기록)을 따랐다 |

| `db/dev-seed.sql` | PCB 부품(`PCB-001 Main PCB`, 재고 0, 공장 납기 7일) 추가 | PCB 부품이 없어 PCB 결함에 추천할 부품이 없었다. 재고 0이라 공장 발주 분기도 보인다 |

## 확인한 흐름 (프론트 프록시 경유)
접수 → AI 진단 → (사진 요청 → 지정 사진 → 재개) → 진단 완료 → **진단 확인 → 수리 중 → 리포트 저장·확정 → 종결**
