# 수정·삭제 요약 (2026-10-21)

통합하면서 고치거나 잘라낸 것만 한 줄씩 적었다. 이유와 파일 위치는 `변경메모.md`에 있다.
팀 레포(backend, agent-server, frontend)에는 push하지 않았다. 고친 내용은 `patches/`에 있다.

## 오류 수정
- 에이전트: 후보가 점수 순이 아니었다(0.79가 1순위, 0.95가 2순위). 점수 높은 순으로 정렬했다.
- 에이전트: 실제 RAG 서버를 써도 도구 이력에 "mock"으로 찍혔다. 서버 이름으로 구분하게 했다.
- 에이전트: RAG 유사도가 0%로 나오고 사례 원문이 네덜란드어 그대로 나왔다. 유사도를 유지하고 한국어로 번역했다.
- 에이전트: 추천 부품이 늘 빈 목록이었다. `/internal/parts`에서 검출 부위와 같은 종류 부품을 넣게 했다.
- 에이전트: 사진 후보의 근거에 관계없는 RAG 사례가 붙었다. 사진 후보에서는 뺐다.
- 에이전트: 추가 사진 요청(PHOTO_REQUESTED)이 막혀 있었다. 요청과 재개(DIAGNOSIS_RESUMED)를 열었다.
- 에이전트: GPT가 자동차 부위 이름을 보고 기계 결과를 무시했다. 프롬프트에 "모두 이 청소기 부품 결과다"를 넣었다.
- 백엔드: 사진이 전부 GENERAL로 저장돼 PCB와 모터 사진을 구분하지 못했다. 접수와 추가 사진에 target을 받게 했다.
- 백엔드: 진단 완료에서 수리 중으로 넘기는 API가 없어 리포트 화면이 안 열렸다. `POST /api/repairs/{id}/approval`을 추가했다.
- 백엔드: 접수가 firmware를 필수로 받는데 제품 데이터에 없어 접수가 실패했다. seed에 `1.0.3`을 넣었다.
- 백엔드: 프론트 예시 시리얼 `RC2026000187`이 DB에 없어 조회가 실패했다. seed에 추가했다.
- 백엔드: PCB 부품이 없어 PCB 결함에 추천할 부품이 없었다. 재고 0인 `PCB-001`을 seed에 추가했다.
- 프론트: 후보를 필드 이름이 다른 곳에서 읽어 원인 이름과 설명이 빈칸이었다. `result.candidates`에서 읽게 했다.
- 프론트: 에이전트 단계 이름이 화면과 달라 진행 표시가 멈췄다. 단계 이름을 매핑했다.
- 프론트: SSE가 화면에 닿지 않아 '분석 중'에서 멈췄다. 진행 중이면 4초마다 다시 조회하게 했다.
- 프론트: 로그인 화면이 이메일 형식만 받아 `tech1` 같은 dev 계정이 막혔다. 이메일 검사를 뺐다.

## 이름 통일
- 사진 종류를 백엔드 DB 기준 `PCB / MOTOR / SW / GENERAL`로 맞췄다. `MECHANICAL`은 `MOTOR`로 바꿨다.
- 옛 이름 `MECHANICAL`로 와도 백엔드와 프론트가 `MOTOR`로 받아 준다.
- 에이전트 도구 이름 `analyze_mechanical`을 `analyze_motor`로 바꿨다.
- 원인 코드 `DETECTED_PCB`를 `PCB_MISSING_HOLE`처럼 결함 이름이 보이게 바꿨다.

## 잘라낸 것
- 프론트 진단 결과의 "수정 의견 작성" 버튼을 지웠다. 상태가 안 바뀌고 이력만 남았다.
- 프론트 진단 결과의 "추가 분석 요청" 버튼을 지웠다. 재진단 API가 없다.
- 프론트 본사 검토 상세의 "재분석 요청" 버튼을 지웠다. 재진단 API가 없다.
- 예전 에이전트 합본 브랜치 `feat/skeleton-merge`와 그 패치(agent-server-0002~0005)를 버렸다. 홍은비 `feat/harness-hardening` 기준으로 다시 맞췄다.

## 임시로 넣은 것 (나중에 빼거나 바꿀 것)
- 찌그러짐 모델은 자동차 외판 모델이다. 출력 이름만 `dent / breakage`로 바꾸고 원래 이름은 `raw_label`로 같이 보낸다. 청소기가 아닌 사진 30장 중 20장에서 결함을 냈다(오탐 많음). 교체해야 한다.
- `DEMO_FORCE_PHOTO=1`이면 첫 진단은 무조건 추가 사진을 요청한다. 시연용이고 기본은 꺼져 있다.
- `auto_photo.py`는 프론트 추가 사진 화면 대역이다. 60초 동안 아무도 안 올리면 지정 사진을 제출한다.
- 로컬 통합 DB의 세 계정 비밀번호를 `1234`로 바꿨다. 로컬 전용이다.

## 남은 것
- 프론트 화면을 브라우저로 직접 확인하지 않았다.
- 에러코드 해석은 출처(에러코드표)가 없어 빈 배열이다.
- business-mcp는 도구 이름이 안 맞고 DB에 직접 접속한다. Spring dev는 가짜 MCP를 쓴다.
- 에이전트 수정분은 홍은비 확인이 필요하다.
