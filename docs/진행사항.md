# 진행사항 (2026-10-21)

## 지금 상태
- 이 레포가 팀 메인이다. `main` = 항상 돌아가는 종합본.
- 에이전트·백엔드·프론트·Rag_mcp·MCP를 한 레포에 합쳤다. 무엇을 왜 고쳤는지는 [개조내역.md](개조내역.md).
- 새로 clone해서 끝까지 돌려 확인했다: 접수 → AI 진단 → 추가 사진 요청 → 재개 → 진단 완료 → 진단 확인 → 리포트 확정 → 종결.
- 실행은 `./setup.sh` 한 번, 그다음 `./run.sh` / `./stop.sh`. 자세한 건 [README.md](../README.md).
- 로그인: 기사 `tech1` / `1234`, 본사 `quality` / `1234`.

## 작업 방법 (브랜치)
1. `main`에서 브랜치를 판다: `git switch -c feat/이름-작업` (예: `feat/sehyun-history`)
2. 작업하고 그 브랜치에 push한다. `main`에 직접 push하지 않는다.
3. PR을 올린다. 통합 담당(유길선)이 합쳐서 돌려 보고 `main`에 올린다.
4. 남의 코드를 고칠 때는 `[통합]` 주석으로 이유를 남긴다.

## MCP 출력 형식 (10/21 확인)
- PCB MCP: 결함마다 `type`(6종), `confidence`, `box_xyxy`(픽셀 좌표) + 박스 그린 사진
- 기계 MCP `detect_surface_defects`: 같은 형식. 6종 crazing, inclusion, patches, pitted_surface, rolled-in_scale, scratches
- 점검 안내·추가 질문·유사 사례는 우리 MCP가 아니라 Rag_mcp(`guidance.py` `integrate_evidence`)가 만든다
- Rag_mcp에는 라벨 이름만 넘어가고 좌표는 안 넘어간다 → 리포트에 "위치 미확인"으로 나온다
- 화면의 이상/확인 필요/정상은 신뢰도 기준(0.8/0.5)으로 프론트가 붙인 것이다 (`frontend/src/api/adapters/diagnosis.ts`)

## 실행 시 주의
- 워커 로그에 `GPT 꺼짐: 규칙으로 대신`이 나오면 레포 맨 위 `.env`에 `OPENAI_API_KEY`가 없는 것이다. 키를 넣고 워커만 다시 켠다
- 8000 포트의 옛 agent-server mock은 안 쓴다. 같은 Kafka group이면 명령을 나눠 가지니 꺼 둔다
- 업무 MCP는 run.sh가 로컬(8015)로 띄운다. `.env`에 `BUSINESS_MCP_URL`(ngrok)이 있으면 그쪽을 쓰니 지운다. 가짜로 돌리려면 `REAL_BUSINESS_MCP=0 ./run.sh`
